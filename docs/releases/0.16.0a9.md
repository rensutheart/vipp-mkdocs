# VIPP 0.16.0a9

VIPP 0.16.0a9 is an alpha patch for workflow recovery and interaction. It
refines recovery eligibility, canvas gestures, calculation progress and Crop
viewer updates without changing scientific calculations or schema numbers.
Unfinished AI assistant, agent, MCP and webhook features are not included.

Use the [canonical GitHub release](https://github.com/rensutheart/napari-vipp/releases/tag/v0.16.0a9)
for the exact wheel, source archive, unsigned Windows x86-64 installer and
separate unsigned, unnotarized, CPU-only macOS Apple Silicon and Intel
packages, each with its matching checksums. The Python package is also on
the [exact PyPI version page](https://pypi.org/project/napari-vipp/0.16.0a9/).
Follow the [installation instructions](../getting-started/installation.md).

## Recovery without untouched startup tabs

- New recovery copies skip the initial **Untitled** workflow if you leave it
  unchanged. Loading its automatic starter preview is not an edit.
- Editing the startup workflow keeps its working copy recoverable as usual.
  Recovery still opens new unsaved tabs; ordinary workflow files are not
  overwritten.
- Manual steps and file-writing nodes stay paused after recovery. Recovery
  does not restore source data, cached results, Undo history or Batch settings.

See [Recover interrupted workflows](../how-to/save-share-export.md#recover-interrupted-workflows).

## More predictable canvas and progress

- Panning starts with a new press-and-drag on the canvas and stops when the
  drag is interrupted. Pointer movement alone does not start a pan.
- Dropping a node from the library or adjusting an inspector slider does not
  start a canvas pan, including while a node is calculating.
- Routine calculation progress keeps the footer height steady as the run
  advances. Long warnings and errors can still wrap so they remain readable.

See [Toolbar and feedback](../reference/interface.md).

## Steadier Crop viewer updates

- Crop Stack coordinates its source-image and outline updates with napari's
  layer-list changes when selecting or inspecting the node.
- Changing margins reuses the unchanged source image instead of repeatedly
  assigning its data. A changed source or calibration still updates the
  display.
- The crop margins, preview-to-commit behavior, output origin and scientific
  crop result are unchanged.

See [Crop an image or volume](../how-to/crop-images.md).

## Compatibility and qualification boundary

Workflow, Batch configuration and manifest schemas remain **6**. Windows
update methods, installer ownership rules and scientific GPU admission are
unchanged. Keep original workflows and data, regenerate Python exports with
the installed version and recheck representative results.

The [qualification declaration](https://github.com/rensutheart/napari-vipp/blob/v0.16.0a9/docs/release-qualification-baseline.md)
distinguishes the affected recovery, interaction and viewer checks from
carried-forward evidence. These presentation and lifecycle fixes do not
establish a full installer lifecycle or validation for every image, GPU or
workflow.
