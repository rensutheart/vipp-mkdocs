# VIPP 0.16.0a5

VIPP 0.16.0a5 focuses on safer workflow persistence, portable paths, clearer
graph editing and guided Windows GPU setup. It does not include the unfinished
AI assistant, agent/MCP, webhook-bot or saved assistant-session features.

Use the [canonical GitHub release](https://github.com/rensutheart/napari-vipp/releases/tag/v0.16.0a5)
for the exact wheel, source archive, Windows installer, separate Apple
Silicon/Intel macOS packages and checksums, or the
[exact PyPI version](https://pypi.org/project/napari-vipp/0.16.0a5/).
Verify installer hashes before opening them. Desktop installers are unsigned
alpha builds; macOS packages are also unnotarized and CPU-only. Follow the
[installation instructions](../getting-started/installation.md).

## Keep and move your work

- **Crash recovery** keeps separate graph working copies and offers interrupted
  named/unnamed tabs as new unsaved recovered tabs. It does not overwrite the
  original workflow or restore calculated arrays, tables, Undo history or
  in-flight work or the Batch workspace/configuration. Save Batch configuration
  separately. It is not a source-data backup; calculate explicitly after
  recovery. See [Recover interrupted workflows](../how-to/save-share-export.md#recover-interrupted-workflows).
- **Portable paths** resolve local workflow, batch and exported-Python paths
  from their saved document's folder where possible. Copy the documents and
  data together while retaining the folder structure. Saving elsewhere does
  not copy data; destinations on another drive/share remain absolute. Review
  batch Skip/Overwrite choices after relocation. See [Save, share and export](../how-to/save-share-export.md).
- **No-overwrite image writes** stage a complete result before atomically
  publishing it only if the destination is still absent. Existing outputs,
  including ones created during saving, are not replaced. If the filesystem
  cannot provide safe no-replacement publication, the write fails rather than
  silently falling back to an unsafe overwrite. This is not one transaction
  across every batch output and provenance file. See [image write safety](../reference/import-export.md#no-overwrite-image-writes).

## Clearer setup and editing

- **Set up GPU… / Repair GPU setup…** offers a reviewed, separate Windows CUDA
  installation of the exact VIPP build. Status cards explain the next action;
  advanced commands and technical logs start collapsed. Verification does not
  install packages. **Open VIPP with GPU** starts another window; current
  workflows stay open and are not transferred automatically. See [in-app GPU setup](../getting-started/windows-cuda.md#set-up-gpu-from-inside-vipp).
- Windows setup checks **Apps & Features** registration before downloads or
  environment replacement. Unsafe registration/recovery conflicts offer
  **Get setup help**, not a retry loop. See [installation troubleshooting](../getting-started/installation.md#troubleshooting).
- Graph wires use clearer lanes and bounded shorter routes; tunnel conversion
  preserves connections as one undoable edit. A minimized floating VIPP window
  can be restored from its original napari Plugins menu. Native Linux/macOS
  window-manager behavior is a separate qualification boundary. See [graph editing](../how-to/edit-graph.md).
- Workflow/Results readiness checks no longer discard queued thumbnail work or
  leave its busy indicator stuck. This is presentation cleanup, not a change
  to image measurements or statistics.
- Image-registration guidance can wrap onto more lines without overlapping
  the inspector sections below it.

## Compatibility and limits

Workflow, batch-config and manifest schemas remain **6**. The operation
catalogue, scientific algorithms and GPU admission regions are unchanged.
Preserve original workflows, data, environments and decisive results; regenerate
Python exports with the installed version and recheck representative outputs.

The [qualification declaration](https://github.com/rensutheart/napari-vipp/blob/v0.16.0a5/docs/release-qualification-baseline.md)
separates changed-domain checks from carried-forward evidence. Consult the
release record for exact source, platform and artifact results. Local tests do
not establish a full frozen Windows GUI installation/recovery lifecycle, broad
filesystem coverage, large-volume performance or biological validity. GPU setup
does not admit additional devices, providers or scientific operation regions.
