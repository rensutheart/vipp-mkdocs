# VIPP 0.15.0a1

**A clearer path from a workflow to a reviewed batch result.** This alpha
redesigns batch processing and the inspector, adds more useful plots and tables,
and extends eligible measurement acceleration. It also improves the everyday
work of loading an image, following progress, and understanding what was saved.

Use the [canonical GitHub release](https://github.com/rensutheart/napari-vipp/releases/tag/v0.15.0a1)
for packages, installer assets, checksums, and release evidence, or the exact
[PyPI version](https://pypi.org/project/napari-vipp/0.15.0a1/) for a manual install.
See [installation](../getting-started/installation.md) for platform instructions.

!!! warning "Alpha software"
    Preserve original workflows, configurations, inputs, and decisive outputs.
    Review known data after upgrading; a successful load is not evidence that
    a scientific analysis remains valid. Read the upgrade notes below before
    replacing an earlier environment.

## Batch processing follows four clear stages

**Setup → Items & outputs → Overrides → Run & results** separates preparing a
collection from calculating it. The next action and activity stay visible in
the footer.

- Files appear before slower metadata and exact-content checks finish, with
  active-file feedback and checked counts. Check does not calculate images.
- **Preview selected** is a separate optional calculation of one sample through
  the graph. The representative toolbar links back to that item's batch details.
- Planned outputs emphasize the producing node, data kind, and format; exact
  file paths remain available when needed.
- Parameter overrides have labelled searches, readable workflow defaults,
  bulk editing, and distinct selection versus reset actions. Run/Bypass choices
  form a matching collapsible section with highlighted exceptions.

The [batch guide](../workflows/batch-processing.md) includes refreshed screenshots
and a walkthrough using the bundled three-pair synthetic example.

## Keep some outputs and rerun others

Right-click an item to **Keep existing outputs**, **Rerun and overwrite
outputs**, or **Use batch default**. Choices are saved against exact samples
and destinations, not row positions. A file-policy-only change updates the
checked plan without repeating source inspection.

The interface distinguishes files to create, existing files to keep, files to
overwrite, and unresolved decisions. Keeping some files still permits missing
outputs to be created. Protected inputs, duplicate destinations, and explicitly
protected outputs remain safety errors. An existing file is never represented
as a newly calculated result merely because it was found on disk.

## Follow processing and understand the result

Preparation identifies what is happening before the first sample starts. Run
performs one final collection validation, and its worker reuses that fresh plan
instead of repeating the same collection scan. Exact per-item checks remain
active during processing.

The upper progress label shows the sample and **Running (node 12/32)**; the
lower one uses the node's readable name without repeating the filename. Two
bottom-aligned lines of reserved text space reduce movement as messages wrap.

Completed and stopped batches now show a **readable report inside Run & results**:
elapsed time, item outcomes, saved versus kept files, and expandable failure
reasons. Selecting a row shows that item's outputs; only its underlined name
navigates to item review. **Refresh file status** checks disk presence, not a
new scientific plan. The archived manifest JSON remains secondary technical
evidence, not the main human-readable report.

A cooperative stop is no longer incorrectly classified as failed CPU/GPU
cleanup. Genuine cleanup failures still block unsafe reuse of the process.

## A redesigned inspector, plots, and tables

The inspector organizes sections by scientific role: connected inputs,
parameters, mask occupancy, object sizes, measurement results, metadata, and
compute evidence. Heavy diagnostics run outside ordinary node dragging and
unnecessary refreshes.

- **Result tables** open in resizable, sortable windows with units and CSV/TSV
  export. Sorting changes the view only; export preserves scientific row order.
- **Intensity Histogram** is a new manual graph node for reproducible scalar or
  multichannel distributions. Saved bin settings produce a table of counts,
  fractions, densities, and cumulative values, with excluded values accounted
  for in metadata. Redrawing uses that table rather than rescanning source data.
- **Scatter pop-outs** support up to 4,096 density bins per axis through
  background, memory-gated work. Zero-inclusive shared axes, equal-axis scales,
  and populated-data zoom improve interpretation. Plot display controls do not
  change the full ROI used for exact metrics.
- Overlapping channel histograms have clearer colours and translucent fills.

See [inspection](../how-to/inspect-outputs.md),
[measurement tables](../workflows/object-measurements-tables.md), and
[colocalization](../workflows/colocalization-association.md).

## Measurement acceleration and everyday workflow improvements

Eligible NVIDIA environments gain **hybrid Measure 3D Mesh Morphology** and
**Analyze Skeleton** measurement paths. Mesh label preparation can run on GPU;
marching cubes, convex hulls, and public table construction remain CPU work.
Skeleton measurement accepts supported already-skeletonized Boolean inputs;
this does not add GPU skeleton thinning. The [compute matrix](../how-to/choose-compute.md#gpu-regions-in-0150a1)
sets out the limits rather than promising universal speedups.

The toolbar now groups document, batch/display, execution, and graph-navigation
actions more clearly. Drop an image file onto an Image Source card, or paste a
copied file or image with ++ctrl+v++ / ++cmd+v++. File-backed metadata and raw
clipboard RGB/RGBA semantics are handled distinctly.

**Find fastest** shows total elapsed and current-stage time during long
benchmarks. A ticking timer indicates a responsive interface, not estimated
completion or proof that an atomic CPU call is advancing. Cancellation and time
limits take effect at safe checkpoints.

Reliability fixes cover source/cache reuse, mixed-rank time/channel navigation,
Crop/Inspect layer lifetime, colour interpretation, and Combine Channels colour
saving/invalidation. A failed source replacement no longer presents unrelated
downstream pixels as current results.

The release contains **115 registered operations** (**113** visible in the
palette), **19 example workflows**, and **15 synthetic samples**. The new
Exhaustive Inspector Showcase exercises all palette operations in seven
synthetic-data lanes; it is a review fixture rather than the shortest tutorial.

## Upgrade notes and limits

- **Batch configuration version 6** adds individual existing-file choices and
  reads supported versions 1–5. Workflow schema 6 and manifest schema 5 are
  unchanged. Earlier VIPP versions limited to batch config 5 cannot read a
  newly saved version-6 config.
- **ImageJ Default Threshold (8-bit)** replaces the public method dropdown with
  fixed Default behavior. Older ImageJ Triangle choices retain their distinct
  legacy calculation; they do not silently become Default or generic Triangle.
  The implementation remains experimental and source-aligned to ImageJ 1.54p;
  independent ImageJ-generated golden parity is not claimed.
- **Clip** is renamed **Clamp Intensity** without changing its bound operation.
  **Minimum Threshold** more clearly distinguishes histogram-valley detection,
  histogram smoothing, and the convergence safety limit.
- Legacy scatter-raster graph nodes still run but are hidden from the palette.
  Use the metrics-node pop-out for new interactive plots.
- Regenerate exported Python after upgrading; exported programs require the
  exact VIPP runtime version.

Windows installers are unsigned. Apple Silicon and Intel macOS packages are
unsigned, unnotarized, and CPU-only. Use matching checksums and official assets.
Most graph paths remain eager/in-memory; this release does not add general
lazy/chunked execution. Large source files can take time to fingerprint, and
active library calls or writers may finish a safe unit before stopping.
