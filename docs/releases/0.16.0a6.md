# VIPP 0.16.0a6

VIPP 0.16.0a6 improves startup feedback and Windows setup reliability.
Scientific algorithms, image interpretation, compute policy and schema numbers
are unchanged.

Use the [canonical GitHub release](https://github.com/rensutheart/napari-vipp/releases/tag/v0.16.0a6)
for the exact wheel, source archive, unsigned Windows installer, separate
CPU-only unsigned/unnotarized macOS packages and matching checksums, or the
[exact PyPI version](https://pypi.org/project/napari-vipp/0.16.0a6/).
Follow the [installation instructions](../getting-started/installation.md).

## Earlier feedback, background preparation

- The splash appears before the main application process starts. Its clock and
  minimize/hide controls remain responsive while Windows creates that process.
- On Windows, prepared branding and normal vector lettering show the live
  version, stage and elapsed time before system fonts finish preparing. The
  loading message uses Inter Medium throughout startup.
- OME-XML and OME-Zarr libraries warm in the background after the interface
  opens. Later file selection reuses them. A file selected immediately may
  still wait for its library; early TIFF loading uses a worker while XML support
  is warming. No source files are opened or workflows calculated by warming.
- Retained startup logs include elapsed, CPU and per-stage timing. See
  [startup guidance](../getting-started/launching.md#during-startup) and
  [slow startup](../troubleshooting/performance.md#if-startup-is-slow).

## More reliable Windows setup

Setup briefly retries sharing locks when publishing or restoring shortcuts,
installation records and retained artifacts. It prepares shortcuts privately
before publishing them atomically. A persistent lock produces a clear next
step while ownership, transaction and rollback protections remain in force.
See [installation troubleshooting](../getting-started/installation.md#troubleshooting).

## Limits and compatibility

This release does not promise a fixed launch time. Security scanning and cache
state can dominate startup; security settings are unchanged. The
[Windows investigation](https://github.com/rensutheart/napari-vipp/blob/v0.16.0a6/docs/benchmarks/windows-startup-2026-10-21.md)
distinguishes installed measurements, recovery-paused launches and controlled
rendering checks. It does not establish a reboot-cold or same-version comparison
between computers. Closing immediately during an active native import may wait
for that import to finish safely.

Workflow, batch-config and manifest schemas remain **6**. The operation
catalogue, scientific kernels, GPU admission and dependency pins are unchanged.
Preserve original workflows/data, regenerate Python exports with the installed
version, and recheck representative outputs. The
[qualification declaration](https://github.com/rensutheart/napari-vipp/blob/v0.16.0a6/docs/release-qualification-baseline.md)
identifies changed-domain checks and carried-forward evidence; focused tests do
not establish a complete fresh-user installer lifecycle or all display settings.
